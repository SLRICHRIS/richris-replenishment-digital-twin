ⓘ Model & measurement boundaries +

This interactive 3D scene uses the presentation's three-robot replenishment workflow. Each robot carries 30 units along simplified aisle routes. Battery drains during motion and recharges at the depot. Shelf inventory decreases at a configured consumption rate. Geometry and dimensions are illustrative. Lighting, metal surfaces, concrete and cartons are rendered in real-time 3D. Wheel and payload animation follows simulation state. A simpler compatibility view is used when WebGL 2 is unavailable. A conservative shared-aisle reservation allows one virtual robot journey at a time, including its return to the bay. Staging routes avoid the other occupied bays. This is a discrete route model, not physical collision avoidance or a dynamics model.

Sensor cones are illustrative visibility overlays. The +5s layer projects motion along each assigned route using current speed and pause/stop state. It does not predict interactions or new assignments. Dispatch estimates integrate aisle speed and the complete return journey. A 15% return battery reserve is required. Inventory projections include feasible approved deliveries in queue order; unapproved or paused deliveries are excluded. Demand and speed are assumed constant over the forecast window.

Prediction runs in a separate browser Web Worker. Browser command handling and forecast round-trip timings are diagnostics, not validated physical override latency, Wi-Fi delay or system reliability. The Hardware workspace can receive real ESP32 telemetry through a configured secure MQTT broker. The Floor source selector separates that telemetry from this simulation. Physical poses require calibrated localization; the warehouse geometry is a reference layout. Live data never drives the simulation’s stock, missions or forecasts. No motor commands are transmitted. Simulation time pauses while the tab is hidden or the live floor is selected.
