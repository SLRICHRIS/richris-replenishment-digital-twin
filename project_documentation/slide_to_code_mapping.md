# Presentation → Python implementation

Source deck: **Digital_Twin_Modelling_Equations_and_Python_S_L_Richris.pptx**, 15-slide version. Equation/code slide pairs are preserved. Paths below are relative to the repository root; module paths are within `backend_streamlit_and_telemetry/predictive_twin/`.

Inventory is not measured by encoders/MPU6050/INA219. Synthetic runs never update physical stock. |

Every physical quantity uses SI units except explicitly labelled Ah, Wh and hours. `theta` is an unwrapped angle in radians, x/y in metres; origin is local and unsurveyed. SOC is a fraction internally and displayed as %. `dt` is seconds from device monotonic time. Left/right signs are positive for forward rolling; positive heading/yaw is counterclockwise. `radius_left_m`, `radius_right_m`, `track_m`, count resolutions, `capacity_ah`, `initial_soc` and `gyro_bias_rad_s` are separately calibrated for each robot. `residual_threshold_rad_s` and `residual_hold_s` are measured-trial settings, not paper constants.

**[A]** Carlos Villagomez Alfaro et al., *Real-to-Sim Calibration and Cross-Domain Trajectory Validation of a Low-Cost Multi-Sensor UGV Digital Twin*, Sensors **2026**, 26(18), 5729. [Paper / DOI](https://doi.org/10.3390/s26185729). PDF pages are counted from page 1, not browser HTML lines. The paper includes hardware beyond our BOM; its validated navigation accuracy does not transfer to this robot.

**[B]** Movassagh et al., *A Critical Look at Coulomb Counting Approach for State of Charge Estimation in Batteries*, Energies **2021**, 14(14), 4074. [Paper / DOI](https://doi.org/10.3390/en14144074). This is the verified battery reference in the final deck; no unverified 2025 battery model is attributed to it.

**[C]** Ferrari et al., replenishment digital-twin workflow reference, **2024**, [DOI 10.1007/s00170-023-12660-y](https://doi.org/10.1007/s00170-023-12660-y). Sensor prediction/anomaly equations are not attributed to this workflow paper.
